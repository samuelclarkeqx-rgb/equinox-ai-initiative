03 · Agent Perspectives

Ground-Level Insights

To ensure AI solutions address real problems rather than assumed ones, we conducted direct conversations with the Process Owner (Kyle) and a front-line agent (Jacob Miller).

Kyle — Process Owner & QA

  • QA Audits — Automatically audit tickets and flag those with poorest customer experience
  • Weekly & Monthly Reporting — Auto-generate performance reports with metrics and trends
  • Pending Follow-Up Reminders — Automatically remind agents about tickets due for follow-up
  • Automated Follow-Ups & Closure — Auto follow-up after 48 hrs, auto-close after defined period
  • Agent Feedback — Generate actionable feedback based on ticket handling and performance trends
  • Quality Feedback — Identify recurring quality gaps and provide targeted recommendations

Jacob Miller — Front-Line Agent

Pain Point 1 — Manual Follow-Up Tracking

Jacob currently has to manually track which tickets need a follow-up after 48 hours of no customer response. There is no automated reminder — agents rely on memory or manual checks. Jacob specifically asked for an automation that sends the first follow-up automatically, with him handling subsequent follow-ups himself.

Pain Point 2 — Inaccurate Chatbot Summaries

The client's Zendesk chatbot generates a ticket summary — but it is often inaccurate. A second summary from Corey (client's system) is more useful as it includes guided steps and sibling ticket links. Agents currently read both summaries manually and piece together the context themselves — adding significant time at the start of every ticket.

Pain Point 3 — Repetitive Google Form Entry

For certain ticket actions, agents must fill a Google Form with agent name, date, and ticket number — every single time. This same information is already available in Zendesk. Agents are manually re-entering data the system already has.

05 · Proposed AI Roles

3 AI Roles for Pilot Phase

We will build the smallest set of AI capabilities needed to test the highest-value roles first.

🤖 AI Follow-up Agent — alongside every Agent

PurposeAutomatically send the first follow-up email after 48 hours of no customer response — so no ticket is forgotten.
ResponsibilitiesMonitor all open tickets, detect 48-hour no-response threshold, send templated follow-up, flag ticket for agent.
BoundariesSends only the first follow-up. All subsequent follow-ups handled by agent. Never closes ticket without agent confirmation.
InputsZendesk ticket status, last customer response timestamp, follow-up email templates.
OutputsAutomated follow-up email sent to customer, ticket flagged in agent view.
MeasurementsReduction in DSAT due to delayed response, FRT improvement, tickets auto-followed-up per week.

📋 AI Ticket Brief Agent — alongside every Agent

PurposeMerge the chatbot summary and Corey summary into one clean, structured brief — so agents start every ticket with full context instantly.
ResponsibilitiesRead both summaries on ticket creation, extract key information, generate a single structured brief with issue, guided steps, and sibling ticket link.
BoundariesGenerates brief only — agent reads and acts. Never modifies original ticket content.
InputsClient chatbot summary, Corey's summary, sibling ticket references.
OutputsOne clean ticket brief — issue summary, guided steps, related ticket links.
MeasurementsAgent-reported time saved per ticket, reduction in escalations due to missing context.

✅ AI QA Agent — alongside Kyle

PurposeAutomatically review all tickets and surface those needing Kyle's attention — so he focuses on the most critical ones.
ResponsibilitiesCheck tone, accuracy, SOP compliance, and completeness of every reply. Score each ticket. Flag priority issues.
BoundariesFlags and scores only — Kyle makes all final decisions on quality and feedback.
InputsAll sent ticket replies, QA scorecard criteria, SOP library.
OutputsAuto-scored ticket list, priority flag list for Kyle, weekly quality summary.
MeasurementsQA coverage rate, flag accuracy, time saved per week for Kyle.

09 · Proof of Concept

AI Follow-up Agent — Working Demo

Before approaching the client, a working proof of concept of the AI Follow-up Agent was built and tested on demo accounts. This confirms the technical feasibility of the solution.

✅ What Was Built & Tested

1. Zendesk API Connection

Connected to a Zendesk trial account via OAuth 2.0 — authenticated and fetching live ticket data using Python.

2. 48-Hour No-Response Detection

Python script reads all pending tickets, calculates hours since last customer response, and flags any ticket exceeding the threshold.

3. Slack Notification — Live & Working

When a ticket exceeds the threshold, an automatic Slack notification is sent to the agent channel — showing ticket ID, subject, and hours waiting. Tested successfully on equinox-test Slack workspace.

Tech Stack Used: Python, Zendesk OAuth 2.0 API, Slack Incoming Webhooks — all on demo accounts. No client data was used or accessed.

Note: This proof of concept was built on demo accounts. Production deployment will require write access credentials from Virtuous — which will be discussed with the client separately.
